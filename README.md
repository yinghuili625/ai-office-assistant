# AI辅助办公应用

这是一个中文本地办公平台，支持任务管理、周期提醒，以及根据素材和固定模板调用模型起草文档。前端使用原生 HTML、CSS 和 JavaScript，服务端使用 Node.js 内置 HTTP 与 SQLite，无需安装第三方 Node.js 包。千问长录音转写另需本机 FFmpeg/FFprobe 音频工具。

## 已有功能

- 工作总览、任务台账、列表与看板，支持搜索、筛选和分页查看全部任务。
- 新建、编辑、改派、开始处理、完成和重新打开任务；所有状态均可编辑。
- 按文本、表格、演示文稿、PDF、图片或不限设置提交形式，完成任务前必须上传符合格式的交付材料。
- 已提交材料下载、删除与恢复，任务操作历史、删除确认、回收站与恢复。
- 每周、每月、每季度、每年固定任务，支持 CSV 批量导入。
- 临期、到期和逾期站内提醒，任务台账导出与 SQLite 数据备份。
- 可选的 Server酱个人微信推送，每天汇总待处理任务，支持测试发送和失败后手动重试。
- AI 文档辅助：自由创建文档模板，支持从历史文档提炼结构与待补充内容；素材导入、可选录音转写、历史样例参考、初稿编辑和人工确认。
- 已确认文档可下载为 Word 或 Markdown；修改后必须重新确认。模板、素材、文档、来源快照和审核记录在本机保存。
- 简洁中文页面，适配桌面与窄屏。
- 任务完成单页：上传素材与模板、AI 生成、在线编辑、保存提交；会议原件与正式交付文件分别保存。

当前版本默认供本机管理员单人使用，业务页面仅监听本机地址。负责人用于任务归属和提醒筛选，目前没有独立用户登录和多人权限。任务管理无需模型账号；AI 功能需要自行配置兼容接口，可选微信推送需要自行配置 Server酱 SendKey。GitHub 上的代码协作与应用内多人共同办公是两件独立的事。

## 获取代码

在仓库页面点击 **Code → Download ZIP** 下载后解压，或复制仓库的 HTTPS 地址进行克隆：

```sh
git clone https://github.com/yinghuili625/ai-office-assistant.git
cd ai-office-assistant
```

下面所有命令都在包含 `package.json` 的项目目录执行。

## 本地运行

安装带安全补丁的 [Node.js](https://nodejs.org/)：24.x 至少 **24.22.1**，或 26.x 至少 **26.12.1**。旧版本会拒绝启动，Docker 基础镜像也已固定到 24.22.1。然后运行：

```sh
node --version
npm start
```

无需执行 `npm install`。启动后打开 [中文工作台](http://127.0.0.1:3080)，在命令行按 `Ctrl+C` 停止服务。本地模式使用内置定时器，每分钟检查固定任务和提醒；电脑关机、休眠或服务停止时不会执行检查。

首次创建数据库时会写入演示任务和固定任务规则。示例只初始化一次，后续启动继续使用已有数据。如希望从空白数据库开始，在第一次启动前设置环境变量 `SEED_DEMO=0`。例如 PowerShell：

```powershell
$env:SEED_DEMO = '0'
npm start
```

直接运行 `npm start` 时，环境变量由当前终端提供，不会自动读取 `.env`。可选变量包括 `PORT`（默认 `3080`）、`DATA_DIR`（默认项目内的 `data`）、`SEED_DEMO`（默认启用演示数据）和 `SERVERCHAN_SENDKEY`（可选微信推送密钥）。

也可以把官网 Windows 便携版解压到项目的 `.runtime/node-v24.22.1-win-x64/`，启动脚本会优先选用其中符合安全版本要求的 Node，无需修改系统安装或全局 PATH。可直接用项目内运行时验证：

```powershell
& .\.runtime\node-v24.22.1-win-x64\node.exe --test
```

### Windows 启动脚本

双击 [启动平台.cmd](启动平台.cmd) 可自动选择可用的 Docker 或本地 Node.js，启动后打开页面；使用结束时双击 [停止平台.cmd](停止平台.cmd)。脚本根据所在目录定位代码和数据，可在不同电脑上的任意项目目录使用。

明确选择本地模式：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\start.ps1 -Mode Local
```

脚本首次运行会自动生成本地 `.env`，其中包含随机调度与工作流密钥。脚本模式如需空白初始化，可先仅生成配置：

```powershell
. .\scripts\common.ps1
Initialize-Platform
```

然后把 `.env` 中的 `SEED_DEMO` 改为 `0`，再启动平台。这只影响数据库的首次初始化，不会清除已有任务。

启动、停止和备份会核对当前目录的实例标识；端口上的平台来自其他目录或旧版本时会明确报错。要同时运行两份副本，可为每份 `.env` 设置独立的 `PORT`，Docker 模式还需设置独立的 `N8N_EDITOR_PORT`（默认 5680）。目录标识由脚本生成，复制项目后重新运行启动脚本即可，不要直接沿用另一目录运行中的实例。

### Docker 与定时工作流

在 Windows 安装并启动 Docker Desktop，执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\start.ps1 -Mode Docker
```

脚本准备密钥并启动应用与 n8n 定时工作流。业务页面仍为 `http://127.0.0.1:3080`，仅供维护的 n8n 编辑器为 `http://127.0.0.1:5680`。首次拉取镜像需要网络。

已有 `.env` 后，也可以使用 Docker Compose：

```sh
docker compose up -d --build --wait
docker compose logs --tail 100 application n8n
docker compose down
```

不要同时使用本地与 Docker 两种方式操作同一份数据库。修改代码后，Docker 模式需重新构建应用镜像才能生效。

## 周期任务与提醒规则

新增或修改周期开始日期、CSV 导入时，日期不得早于当前日期前 365 天，防止年份误填后大量补建。已有规则从更早年份恢复时，只补建最近 365 天内的周期，并记录跳过日期的操作日志；已生成的历史任务保留。每次检查最多新建 100 项，剩余部分在下一次检查继续，重跑不会重复生成。

推迟任务截止日会立即把旧的无效提醒标为已读；改名、改派或调整到期日期时按当前任务信息更新提醒。站内提醒每页 50 条，任务详情的操作记录可继续加载更早内容。

## 完成任务与提交材料

任务的“提交形式”决定支持的文件：

| 提交形式 | 支持的扩展名 |
| --- | --- |
| 文本 | `.txt`、`.md`、`.doc`、`.docx`、`.rtf` |
| 表格 | `.csv`、`.xls`、`.xlsx` |
| 演示文稿 | `.ppt`、`.pptx` |
| PDF | `.pdf` |
| 图片 | `.png`、`.jpg`、`.jpeg`、`.webp` |
| 不限 | 以上全部格式 |

点击“标记完成”后，可上传素材与模板、使用 AI 生成并在线编辑后提交。已有成稿时，在完成页面选择“直接上传成稿”：上传 1—5 个文件，单个不超过 10 MiB，总计不超过 25 MiB，并确认已按交付要求核对内容。系统校验格式、大小和基础文件结构，业务内容由提交人确认。重新打开任务后，再次完成需要提交本次成果；历史材料保留。

任务详情中每份已提交材料旁可点击“删除”，确认后从有效材料列表移除，可在该任务的“已删除材料”中恢复。若删掉最近一次完成任务所提交的最后一份材料，任务自动转为进行中，需要重新上传并核对后完成；删除更早批次的材料不影响完成状态。恢复材料不会自动将任务变成已完成。文件原内容与删除记录保留在业务备份中。

## 个人微信推送

1. 登录 [Server酱](https://sct.ftqq.com/)，取得 Turbo 版 `SCT` 开头的 SendKey，在其控制台绑定本人的微信，并选择微信服务号通道。`sctp` 开头的 Server酱³ Key 用于独立 App，不适用于本功能。
2. 打开应用的 **提醒中心**，配置个人微信推送：填入 SendKey，选择负责人范围与北京时间发送时刻，保存并启用。负责人留空时汇总全部符合条件的任务，填写姓名时只匹配该负责人。
3. 可先发送测试消息，收到后再确认正式配置。测试使用固定虚构内容，也会消耗 Server酱服务额度。

默认关闭推送，默认发送时刻为北京时间 `09:00`。服务运行期间，每天到时后有未完成的临期、到期或逾期任务时，汇总推送一次；站内提醒是否已读不影响汇总。成功记录跨重启去重，失败不自动重试，可在提醒中心手动重试。网络超时可能无法判断服务端是否受理，重试前先查看微信以免重复。所有发送操作限频，约每 60 秒可调用一次；Server酱自身另有通道、额度和频次限制，以其控制台为准。

正式消息仅发送任务标题、负责人和截止日期等摘要，最多 50 条、约 8 KB；超出时提示回到本机查看。任务正文和交付文件不会发送。API 返回成功仅表示 Server酱已受理，不能确认微信最终送达；真实投递需使用自己的 SendKey 和已绑定的通道验收。

页面配置的密钥保存在本机 `data/serverchan.json`，接口不返回密钥。也可使用环境变量 `SERVERCHAN_SENDKEY`，它优先于本机配置；页面无法覆盖或删除环境变量中的密钥。Windows 启动脚本会读取 `.env` 中的该变量，Docker Compose 会将其传入应用；直接 `npm start` 则需要先在当前终端设置环境变量。推荐使用页面配置，勿将 SendKey 放进源码或分享截图。

此功能是一套本机配置对应一个 Server酱接收端，负责人筛选仅控制摘要范围，不代表给每名负责人分别投递。

## AI 文档辅助

### 一页内整理并提交任务成果

在任务清单或任务详情点击 **标记完成**，即可打开同一个完成页面。顶部显示任务负责人、截止日期和交付要求；左侧上传素材、选择或上传模板，右侧直接编辑生成内容。

- 上传会议文档、录音、图片或粘贴文字，勾选本次使用的资料（最多 5 份）。文档在本机提取，原件保留；上传本身不会请求模型。
- 选择已有模板，或直接上传本次模板文件。上传模板仅在本机提取，不必先去模板库新建，初稿保存时会保留本次模板快照。
- 核对模型目的地并勾选同意，点击 **AI 生成内容**。选中的录音、图片会先转写或识别，再结合本任务要求、文字资料与模板生成初稿。
- 在正文中直接修改，可随时 **保存草稿**。核对符合交付要求后，点击 **保存并提交，完成任务**；系统一次保存当前编辑、记录人工确认、生成 Word 并完成任务，无需分别保存、审核或填写质量评价。

同一个浏览器页面内切换其他任务，再回来会保留未保存的正文、文字素材和本次模板；刷新或关闭前仍请保存。模型设置发生变化或服务重启后，旧的发送确认会失效，需要重新读取实际服务地址并勾选同意。此规则同时适用于文档、录音和图片，自动保存素材不会绕过确认。

会议文档和模板支持 .docx/.txt/.md/.csv（1 MiB，提取正文最多 20000 字）。录音原件最多 100 MiB；千问转写自动在本机分段，最长 4 小时，其他兼容转写服务仍限 20 MiB。图片支持 .png/.jpg/.jpeg/静态.webp（10 MiB）；千问还要求图片 Data URI 编码后不超过 10 MiB，建议原图不超过 7 MB。识别失败时原件和已有正文仍保留，可取消勾选该原件并粘贴人工整理文字。直接生成 Word 要求提交形式为“文本”或“不限”；其他格式可使用页面的“直接上传成稿”入口。

正式材料可下载、删除和恢复，提交内容与来源快照保留；只有正式提交才完成任务。已有独立 AI 文档资料库仍可使用。

### 配置模型与独立文档资料库

打开 **AI 文档 → 模型设置**，分别配置“文档生成”“录音转写”“图片识别”三个页签。各项可使用独立服务地址、模型和密钥，录音、图片也可选择“共用文档服务”以兼容旧配置。

| 用途 | 推荐配置 |
| --- | --- |
| 文档生成 | 保留已有 DeepSeek、本机 Ollama 或其他兼容服务；填写完整模型编号 |
| 千问录音转写 | 选千问，模型 `qwen3-asr-flash`，中国内地基础地址 `https://dashscope.aliyuncs.com/compatible-mode/v1` |
| 千问图片识别 | 选千问，模型 `qwen3.5-ocr`，使用上述兼容基础地址 |

百炼密钥须与所选服务地域匹配，模型开通和可用编号以官方为准。已有密钥不会回显；留空保留当前项的密钥，更换该项服务来源时须填新密钥或明确清除旧密钥。独立项不会借用文档密钥。各页签可分别保存并测试；只保存不会请求模型，停用时也可测试，测试需明确同意且可能收费。文档测试发送固定虚构文字，录音测试发送内置短静音，图片测试发送内置带字测试图，均不读取办公资料。静音测试只确认接口可达，不能验证转写准确率。

本机 Ollama 需先安装并启动服务，填写已安装的准确文本模型名称，默认地址 `http://localhost:11434/v1`，无密钥要求时留空。应用请选择本地 Node.js 模式；Docker 容器内的 `localhost` 是容器自身，不能用它访问宿主机 Ollama。其他兼容服务须支持 `/chat/completions`，填写供应商提供的基础地址，不要填写完整调用路径；远程服务仅接受 HTTPS，本机环回地址可使用 HTTP。

千问转写使用 `/chat/completions` 的音频输入，兼容转写使用真正 multipart `/audio/transcriptions`，两种协议不可混用。录音支持 `.mp3/.wav/.m4a/.webm/.mp4/.ogg/.flac`；本版本不使用 realtime 或 filetrans 模型。常见连接问题和处理步骤见 [使用说明](使用说明.md#配置模型)。

官方协议与模型说明：[千问 ASR](https://help.aliyun.com/zh/model-studio/qwen-asr-api-reference)、[千问 OCR](https://help.aliyun.com/zh/model-studio/qwen-vl-ocr)。

### 长录音与本机音频工具

千问长录音先由本机 FFmpeg/FFprobe 检测并转为 16 kHz 单声道 WAV，按 180 秒分段，再逐段发送；原件最多 100 MiB、最长 4 小时，每段 Data URI 编码后最多 10 MiB。文件不会先上传到公共文件地址。首次使用须安装音频工具；Windows 可从 [FFmpeg 官方下载页](https://ffmpeg.org/download.html)所列的 [gyan.dev 构建](https://www.gyan.dev/ffmpeg/builds/)下载并解压到项目上级的 `工具/ffmpeg`（本机为 `E:\AI辅助办公应用\工具\ffmpeg`）。仓库不包含这些工具，换电脑需重新安装，也可将工具加入 `PATH`，或在启动平台前设置 `FFMPEG_PATH`、`FFPROBE_PATH` 为两个程序的完整路径。Docker 需在容器内提供工具，宿主机 Windows 程序不能直接供容器使用。工具缺失时会明确提示，不会假装转写成功。

长转写在后台显示分段进度，一次只处理一个 AI 请求。失败不自动重试，避免重复计费；可复制已经取得的部分文字。重启保留任务中上传的原件和已保存素材，不恢复内存中的转写任务或未完成部分。素材正文最多 60000 字，历史样例最多 20000 字；起草总上下文仍为 60000 字（含模板、任务要求等），长转写需先人工精简再生成纪要。

使用流程：

1. 在素材中粘贴文字或导入 `.txt/.md/.csv/.docx`，单个导入文件不超过 1 MiB，提取后正文最多 20000 字符；导入只在本机提取，不会自动请求模型。正文导入不接受旧 `.doc`、Excel 附件（可另存 CSV）、扫描 PDF 或图片，图片请使用任务资料的识别入口。导入 Word 不保留原版式。录音在明确确认后发送至已配置的转写接口，转写结果需保存为素材。
2. 选用或新建文档模板，不限制文档类型。新建窗口中可导入历史 `.docx/.txt/.md/.csv`（最多 1 MiB），或粘贴历史正文；先在本机提取、预览，核对模型服务并同意后点击“识别结构与待补充内容”。模型会提炼章节、写作要求及今后使用时要提供的信息；检查结果后点击“应用到模板”，修改核对并保存。识别不会自动保存原文、创建素材或改写模板，历史事实只供格式参考。历史成稿也可另存为“历史样例”，供起草时参考行文，不是模型训练，也不能提供本次会议的事实。
3. 选择本次素材（最多 5 份）、历史样例（最多 3 份）及可选关联任务，核对模型服务地址并确认后生成；总上下文不超过 60000 字符。只发送所选资料和模板，不自动读取整个任务库或任务交付文件。
4. 根据原始材料校核人名、日期、数字、决议和【待核实】内容，编辑保存，再登记初稿质量和审核意见、确认使用。确认前不能导出；确认后修改需要重新审核。
5. 下载 Word（`.docx`）或 Markdown（`.md`）成稿。AI 起草不会自动完成任务；需要交付时，仍按任务原有要求上传成稿并确认完成。

历史样例、来源快照、审核和质量评价用于追溯及改进。可用率按人工对原始初稿的评价统计；项目要求的 60%—70% 可用率仍需少量真实任务逐份实测，本版本不宣称已经达标。没有配置真实服务时，不会用模拟内容代替生成。

模型配置和 API 密钥保存在本机 `data/ai-settings.json`，页面不回显已保存密钥；同一服务来源下留空保存保留原密钥。更改域名、协议或端口后，必须填新密钥或明确清除旧密钥。该文件不包含在业务数据库备份中，迁移时另行安全保留或重新配置；不要上传到 Git 或在聊天中传递。模型服务是否记录请求、额度和费用以所选服务说明为准。

## 数据与备份

业务数据库和交付材料保存在 `data/office.sqlite`，微信发送记录保存在其中的 `serverchan_records` 表。AI 文档模板、素材正文、历史样例、初稿、来源快照和审核记录也保存在 SQLite，均纳入业务备份。可在平台设置下载完整业务备份，也可使用 [备份数据.cmd](备份数据.cmd)。`backups/` 存放本地备份，`data/n8n/` 存放工作流运行数据。

微信设置和 SendKey 单独保存在原子写入的 `data/serverchan.json`，不包含在业务备份中；迁移时应另行安全保留该文件或重新配置，环境变量中的密钥则随本机 `.env` 或终端环境另行保存。恢复较旧的业务备份可能丢失当天发送记录，重新启用推送前先核对微信消息，避免重复发送。

AI 服务地址、模型与密钥另存于 `data/ai-settings.json`，同样需单独安全保留。独立「AI 文档」页面的临时录音仅用于转写，不持久保存原件；任务完成页上传的会议文档、录音和图片原件保存在任务资料中，随 SQLite 业务备份一并保留。

任务清单和提醒由服务端分页，汇总统计仍覆盖全部有效任务；关联 AI 文档时可搜索更早任务。数据库备份按流下载，避免把整份数据库一次读入内存。

原件与交付文件累计默认限制为 **4 GiB**，平台设置显示已用容量。软删除的文件仍占用存储，也计入限额；超过限额时本次上传或提交完整回滚。维护人员可在脚本使用的 `.env` 中设置 `MAX_STORED_BYTES`（正整数字节数）后重启。该额度计算文件原内容，不等于数据库磁盘大小；文字、索引、来源快照和 WAL 另占空间。需要归档时先备份并迁移到独立数据目录，再开始新的工作库；本版本没有自动永久清理历史资料的入口。

代码仓库不应包含 `.env`、`data/`、`backups/`、个人任务、上传文件或运行日志。下载或克隆代码会创建独立的本地数据，不会获得仓库维护者的业务数据。迁移自己的数据时应单独备份，停止服务后再恢复；请勿通过 Git 分享数据库或密钥。

## 开发与验证

```sh
npm test
```

自动化测试使用隔离数据库，覆盖任务流程、周期调度、提醒、导入、材料校验、备份、回收站、Server酱配置与发送行为以及 HTTP 接口。测试替代外部网络调用，不会向真实微信发送消息。

风险回归另覆盖配置版本确认、跨任务草稿保留与异步刷新、周期补建上限、提醒调整、服务端分页、累计容量和流式备份。真实音频工具相关测试在 FFmpeg/FFprobe 缺失时会标记跳过。
